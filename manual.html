1.1 微内核跨进程架构与生命周期

Golem 彻底摒弃了传统单体机器人进程模型，采用宿主（Host）与插件（Plugin）严格分离的多进程微内核架构。每个插件都是独立的 Go 可执行程序，通过 Unix Domain Socket / 本地 IPC 与宿主通过 gRPC 双向高速通信。

🛡️ 进程隔离与容灾沙箱

单个插件出现内存泄露、空指针 Panic 或第三方 API 阻塞崩溃，绝对不会导致 Golem 核心宿主崩溃。操作系统级沙箱保证了核心服务 7x24 小时高可用。

🔄 零重启热加载 / 热重载

更新插件代码并编译后，在微信或控制台执行 /pm reload <name>，宿主将优雅终止旧进程并无缝拉起新进程，微信机器人无需断线重连！

🔌 跨插件能力调度网络

插件之间通过暴露统一 Capability 互相协作。例如：profile 插件调用 statistics 抓取历史发言，调用 ai 总结，调用 gg 渲染成图，极度解耦。

1.2 环境依赖、编译构建与守护脚本

前置依赖：

  • Go 1.26+（需支持现代化 Go Workspaces 架构）
  • FFmpeg & FFprobe：用于多媒体格式转换与音频切片（brew install ffmpeg 或 apt-get install ffmpeg）
  • Silk v3 编码器：项目自带 tools/silk_v3_encoder，负责输出微信原生语音条

常用运维管理脚本：

./start.sh 后台守护启动，输出重定向至 golem.log
./stop.sh 优雅终止主进程与全部子插件进程
./restart.sh 重启服务（等同于先 stop 后 start）
./status.sh 查看进程 PID、存活状态与端口占用

1.3 全局配置文件与所有者 (Owner) 权限模型

Golem 将核心宿主配置与插件业务配置严格解耦：

📄 宿主核心配置 (data/config.toml) Host Only 
# 机器人超级管理员微信号(wxid)
owner = "wxid_your_wechat_id"

# 非管理员发送管理命令时的拦截提示
forbidden = "🚨 权限不足，仅机器人主人允许执行此指令"

# 底层微信 API 接口地址与认证
url = "http://localhost:8085/api"
token = ""

🔒 安全保护：若未配置 Owner，所有高危管理命令（如 /pm、/cm）将被全面拦截或限制，有效防止被群友恶意提权。

📄 插件矩阵总配置 (plugins/config.toml) Plugins Global 
# 每一个插件均具备顶级开关与黑白名单机制
[ai]
enable = true
mode = 'blacklist' # blacklist(黑名单) 或 whitelist(白名单)
limits = []        # 限制生效的群聊或好友 wxid 列表

[ai.config]
active_provider = 'xiaomi'
# ... 各插件专属业务参数

✨ 黑白名单：支持将任意插件限定在特定测试群启用（whitelist），或在特定严肃工作群禁用（blacklist）。

1.4 宿主内置命令行手册 (/pm, /cm)

通过微信私聊给机器人或在受控群内发送斜杠命令即可完成全部运行时管理。当帮助文本超过 3 行时，系统会自动调用 gg 插件渲染为防刷屏高清长图返回！

📦 插件管理器 (/pm - Plugin Manager)

指令 语法与示例 功能说明 快捷复制
/pm list /pm list 列出所有已加载插件的运行状态、优先级与开关
/pm reload /pm reload <name> 热重载指定插件（例：/pm reload ai），无需重启 Host
/pm enable /pm enable <name> 启用已被禁用的插件并开始处理消息
/pm disable /pm disable <name> 静默禁用指定插件，插件不卸载但不响应事件
/pm load /pm load <name> 动态加载一个新插件可执行程序并注入能力
/pm unload /pm unload <name> 卸载指定插件并彻底杀掉其子进程释放系统资源
/pm info /pm info <name> 查看插件的详细元数据、作者、版本与所含指令 Schemas
/pm set /pm set <name> -p 10 -c "..." 在线修改插件优先级(-p)或热写入 TOML 动态配置(-c)

👥 通讯录与群成员缓存管理器 (/cm - Contact Manager)

指令 语法与参数 功能说明 快捷复制
/cm contact /cm contact [key] 刷新并查看联系人缓存，支持 wxid_xxx、nickname::张三、remark::小李
/cm chatroom /cm chatroom [key] 刷新当前群聊的成员缓存名单与昵称备注映射

🛠️ 第三篇：插件开发者快速上手指南

基于官方提供的 github.com/sbgayhub/golem/sdk，5 分钟开发属于你的微信插件

创建插件非常简单，只需实现标准能力接口并在 main() 中调用 plugin.Start()：

package main

import (
    "log/slog"
    "github.com/sbgayhub/golem/sdk/message"
    "github.com/sbgayhub/golem/sdk/plugin"
)

type MyPlugin struct {
    plugin.ConfigAbility[MyConfig] // 注入 TOML 配置读写与热重载能力
}

type MyConfig struct {
    Prefix string `toml:"prefix" comment:"消息前缀"`
}

func (p *MyPlugin) GetMetadata() *plugin.Metadata {
    return &plugin.Metadata{
        Name:        "my_plugin",
        Version:     "1.0.0",
        Description: "我的首个定制微信插件",
        Author:      "Guan",
    }
}

func (p *MyPlugin) OnLoad() error {
    slog.Info("插件加载成功！当前前缀: " + p.Config.Prefix)
    return nil
}

func main() {
    plugin.Start(&MyPlugin{})
}
💡 极速起步建议：直接复制 plugins/example 目录作为工程起点，该模版包含了命令注册、事件监听、跨插件调用与会话状态管理等完整示例代码。

❓ 第四篇：高频问题解答 (FAQ) 与排错清单

Q1: 发送 /pm reload 提示权限不足怎么办？

A: 检查 data/config.toml 中的 owner 是否正确配置为了你本人的微信号 wxid。只有 Owner 才具备宿主系统级管理权限。

Q2: 为什么生成词云或画像提示“查询历史失败”？

A: wordcloud 与 profile 插件强依赖 statistics 插件提供的消息记录能力。请确保 statistics 插件已在 plugins/config.toml 中启用并在正常运行。

Q3: 微信语音条发不出来或显示转圈播放失败？

A: 请检查是否正确安装了 ffmpeg，并在配置中正确填写了 silk_encoder_path。微信原生语音条必须通过 Silk v3 编码器转换为符合规范的音频流。

Q4: 如何避免机器人在大群里频繁被动刷屏？

A: 在 plugins/config.toml 中为 ai 插件调低 reply_rate（如设为 0.05 或 0.1），或在群内使用 /ai session-set -r 0 关闭主动插嘴，此时机器人将仅在被 @ 或引用时回复。
